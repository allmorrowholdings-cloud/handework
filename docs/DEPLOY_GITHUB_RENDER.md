# Push handEwork to GitHub and deploy on Render

## Part A: Create the GitHub repository

### 1. Confirm secrets are excluded

From PowerShell:

```powershell
Set-Location C:\handework
git status
Get-ChildItem -Recurse -Force -Filter .env
```

The `.env` files may exist locally, but `.gitignore` must exclude them.

Also confirm these are not staged:

- `node_modules`
- `.venv`
- `.expo`
- `.npm-cache`
- database files
- ZIP files
- identity documents or job photos

### 2. Initialize Git

```powershell
Set-Location C:\handework
git init
git branch -M main
git add .
git status
git commit -m "Build handEwork skilled-work platform"
```

### 3. Create an empty GitHub repository

Create the repository in GitHub without adding a README, license or `.gitignore`. Then copy its HTTPS URL.

```powershell
git remote add origin https://github.com/YOUR-ACCOUNT/handework.git
git push -u origin main
```

If GitHub asks for authentication, use Git Credential Manager. Do not paste a GitHub token into source files.

### 4. Confirm CI

Open the repository’s **Actions** tab. The workflow runs:

- Web lint and production build
- Flask tests and migration upgrade
- Mobile TypeScript check

Do not deploy a failing commit.

GitHub Actions Node guidance: https://docs.github.com/actions/guides/building-and-testing-nodejs

## Part B: Prepare production services

handEwork uses four runtime services:

1. `handework-web`
2. `handework-api`
3. `handework-worker`
4. `handework-redis`

MySQL is created separately because Render’s managed Blueprint database section is for Postgres. Render documents MySQL as a private service with a persistent disk.

### 1. Create MySQL first

In Render:

1. Follow the official MySQL deployment guide: https://render.com/docs/deploy-mysql
2. Use MySQL 8.
3. Use the Frankfurt region so it matches the application services.
4. Attach a persistent disk at `/var/lib/mysql`.
5. Set:

   - `MYSQL_DATABASE=handework`
   - `MYSQL_USER=handework`
   - `MYSQL_PASSWORD` to a long random value
   - `MYSQL_ROOT_PASSWORD` to a different long random value

6. Keep the service private.
7. Record the private host shown by Render.
8. Build the application URL:

   `mysql+pymysql://handework:URL_ENCODED_PASSWORD@PRIVATE_HOST:3306/handework`

PowerShell can URL-encode the password:

```powershell
[System.Uri]::EscapeDataString("YOUR-PASSWORD")
```

### 2. Deploy the Blueprint

1. Open Render Dashboard.
2. Choose **New > Blueprint**.
3. Connect the GitHub repository.
4. Select the `render.yaml` in the repository root.
5. Review the services before applying.
6. Render will request values for every `sync: false` variable.

Set at least:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | Private MySQL SQLAlchemy URL from the prior step |
| `WEB_ORIGINS` | Temporary web Render URL, later custom domain |
| `PAYSTACK_SECRET_KEY` | Test key first |
| `MAPBOX_SECRET_TOKEN` | Server-only token |
| `EXPO_ACCESS_TOKEN` | Expo push token if enabled |
| `HUBTEL_CLIENT_ID` | Hubtel credential |
| `HUBTEL_CLIENT_SECRET` | Hubtel credential |
| `AWS_ACCESS_KEY_ID` | Bucket-limited identity |
| `AWS_SECRET_ACCESS_KEY` | Matching secret |
| `S3_BUCKET` | Private bucket name |
| `S3_PUBLIC_BASE_URL` | Approved portfolio CDN base, if used |
| `NEXT_PUBLIC_API_URL` | Final `handework-api` HTTPS URL |
| `NEXT_PUBLIC_MAPBOX_TOKEN` | Public web token |

`SECRET_KEY` and `JWT_SECRET_KEY` are generated by Render. Ensure the API and worker use consistent values. If the Blueprint creates different generated values for each service, place the two services in one secret environment group and set identical values manually.

Render Blueprint reference: https://render.com/docs/blueprint-spec

### 3. Check the first deployment

API:

```powershell
Invoke-RestMethod https://YOUR-handEwork-API.onrender.com/v1/health
```

Expected:

```text
status   : ok
database : ok
service  : handework-api
```

Then open the web service URL. Search may return an empty state until a verified artisan is inserted. That is correct.

### 4. Create the production administrator

Use the Render API service Shell. Set temporary environment variables for the command session:

```bash
ADMIN_EMAIL="owner@example.com" \
ADMIN_PHONE="+233XXXXXXXXX" \
ADMIN_PASSWORD="a-long-unique-password" \
python scripts/create_admin.py
```

Remove command history containing the password. Rotate the password after first sign-in.

### 5. Register the Paystack webhook

Use:

`https://YOUR-handEwork-API.onrender.com/v1/webhooks/paystack`

Test a charge. Confirm:

- The provider reports success.
- handEwork records one payment.
- The booking moves to `funded`.
- The wallet held balance equals the payment.
- Repeating the webhook does not duplicate the ledger entry.

### 6. Add the custom domain

In Render, add the web domain. Render will show the DNS records.

After DNS verifies:

1. Set `WEB_ORIGINS=https://www.handeworkapp.com,https://handeworkapp.com` on the API.
2. Add the same final web origin to Mapbox URL restrictions.
3. Update Paystack webhook only if the API domain changed.
4. Redeploy web and API.
5. Confirm HTTPS and redirects.

Render custom-domain guide: https://render.com/docs/custom-domains

## Part C: Deploy mobile builds

### 1. Create EAS configuration

```powershell
Set-Location C:\handework\mobile
npx eas-cli@latest login
npx eas-cli@latest init
```

Replace `REPLACE_WITH_EAS_PROJECT_ID` in `app.json`.

### 2. Add EAS environment values

Set production values in the EAS project:

- `EXPO_PUBLIC_API_URL=https://YOUR-handEwork-API.onrender.com`
- `EXPO_PUBLIC_MAPBOX_TOKEN=YOUR_PUBLIC_TOKEN`
- `RNMAPBOX_MAPS_DOWNLOAD_TOKEN=YOUR_SECRET_DOWNLOAD_TOKEN`

Do not prefix the download token with `EXPO_PUBLIC_`.

### 3. Build internal test apps

```powershell
npx eas-cli@latest build --platform android --profile preview
npx eas-cli@latest build --platform ios --profile development
```

Install and test the full provider sequence before store builds.

### 4. Build production apps

```powershell
npx eas-cli@latest build --platform all --profile production
```

EAS Build documentation: https://docs.expo.dev/build/introduction/

### 5. Submit

```powershell
npx eas-cli@latest submit --platform android --profile production
npx eas-cli@latest submit --platform ios --profile production
```

Store submission guide: https://docs.expo.dev/deploy/submit-to-app-stores/

Submission still needs:

- Apple Developer and App Store Connect access
- Google Play Console access
- Privacy policy and support URLs
- App screenshots and store copy
- Data safety and privacy answers
- Content rating
- Account deletion instructions
- Test credentials for review when required

## Part D: Release procedure after setup

For each release:

1. Create a branch.
2. Make the change.
3. Run web, API and mobile checks locally.
4. Push and open a pull request.
5. Wait for GitHub Actions.
6. Merge to `main`.
7. Render deploys only after checks pass.
8. Confirm `/v1/health`.
9. Run a customer sign-in, search and safe booking read.
10. Watch API, worker, payment and database alerts.
11. Use EAS Update only for JavaScript changes compatible with the installed native build.
12. Create a new native build after native module, permission, plugin or SDK changes.

## Rollback

### Web/API

Use Render’s previous successful deploy. Do not roll database schema backward unless the migration was designed and tested for it.

### Mobile

Stop store rollout or release a corrected build. An installed native binary cannot be removed remotely from a user’s device.

### Database

Restore only after confirming the incident, restore point and data-loss window. First restore to a separate database and validate it.
